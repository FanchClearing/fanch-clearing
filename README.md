# 이의있음! — 팬심 판정 흔들기 배틀

> **억울한 판정은 참지 말고, 폰을 흔들어서 따지세요.**
> 판정은 바뀌지 않지만, 우리 팀 팬심은 이깁니다.

같은 경기를 보는 팬들이 모바일 웹에 모여 **폰을 흔들며 응원**하다가, 억울한 판정이 나오면 **[이의 있음!]** 을 눌러 상대 팀 팬과 **벤치클리어링 배틀**을 벌이는 픽셀 아트 웹 서비스입니다.
해커톤 주제 *"세상에서 가장 쓸데없지만, 쓸모 있는 스포츠 서비스"* 에 맞춘 **젝커톤 2팀**의 작품입니다.

**라이브 데모:** https://jeckathon.web.app

---

## 어떻게 노나요

```
팀 선택·입장 ─▶ 평소 응원 ─▶ [이의 있음!] 기준 인원 달성 ─▶ 심판 휘슬 ─▶ 컷신 ─▶ 흔들기 배틀 ─▶ 결과·메롱 ─▶ 다시 응원 ─▶ 경기 종료
```

1. **팀 선택** — QR을 찍고 LG / 한화 중 응원할 팀을 고릅니다.
2. **평소 응원** — 폰을 흔들거나 [응원!]을 누르면 하트·야구공·응원봉 파티클이 올라가고, 팀별 응원 점수가 **밀어내기 바**를 밀어냅니다. 참여한 모두의 응원이 파티클로 뜹니다.
3. **이의 있음!** — 10초 안에 기준 인원(기본 3명)이 누르면 **픽셀 심판이 휘슬**을 불며 판정이 시작됩니다.
4. **벤치클리어링** — 클로즈업(노려보는 선수) → 와이드(양 팀 선수가 몰려듦) → `START!!`.
5. **흔들기 배틀** — 10초 동안 폰을 흔들거나 화면을 연타합니다. 흔들 때마다 화면이 흔들리고 주먹·별·충돌 파티클이 터집니다.
6. **결과** — 가짜 판정문, 팀 점수, 내 기록, MVP 흔들러 TOP 3. 이긴 팀 팬에게는 상대를 놀리는 **[메롱~]** 버튼이 생깁니다.
7. 15초 뒤 다시 응원으로 돌아가고, 운영자가 **경기 종료**를 누르면 응원 점수로 승패를 가립니다.

## 화면과 주소

| 화면 | 주소 | 용도 |
|---|---|---|
| 팬 입장 (QR 목적지) | `/game/kbo-lg-hh` | 팀 선택 → 게임 화면 |
| 게임 화면 | `/room/kbo-lg-hh` | 응원 · 이의 있음 · 컷신 · 배틀 · 결과 |
| **전광판** (발표용 큰 화면) | `/host/kbo-lg-hh` | 점수·QR·이의 있음 게이지 + **운영 컨트롤** + MVP + 입장 알림 |
| 운영자 (폰용) | `/admin/kbo-lg-hh` | 전광판과 같은 운영 조작 |

> 로그인이 없어서 주소를 아는 사람은 누구나 운영 조작을 할 수 있습니다. 발표용으로만 쓰세요.

## 주요 기능

- **실시간 동기화** — 모든 폰과 전광판이 서버 시각 기준으로 같은 컷신·배틀을 같은 순간에 봅니다 (Firebase Realtime Database).
- **흔들기 센서** — DeviceMotion으로 흔들기를 감지합니다. 센서가 없거나 권한을 거부하면 연타 버튼으로 참여합니다. 배틀 화면은 어디를 눌러도 1회로 셉니다.
- **픽셀 비주얼** — 야구장, 선수, 심판, 파티클, 글러브까지 **전부 코드로 그린 스프라이트**입니다 (외부 이미지 에셋 없음).
- **소리·진동** — 장면별 음악(시작/배틀/종료, 무한 반복), 휘슬 효과음, 시작 진동 3번·종료 진동·흔들 때 짧은 진동(안드로이드).
- **운영 컨트롤** — 경기 시작/종료, 벤치클리어링 강제 시작, 다음 판정, 이의 있음 발동 기준 인원, 팀별 표시 인원 가감, 배틀 시간(5~60초).
- **안정성** — 새로고침해도 내 점수와 팀이 복구되고, 오류는 픽셀 토스트로 알리며, 새 버전이 배포되면 스스로 감지합니다.

## 기술 스택

- **Vite + React 18** (JavaScript), react-router-dom v6
- **Firebase** — Realtime Database(상태 동기화) + Hosting(HTTPS 배포). Auth는 쓰지 않습니다.
- qrcode.react (전광판 QR), HTML Canvas (픽셀 그래픽), 순수 CSS, Galmuri11 폰트
- 상태관리 라이브러리·UI 프레임워크·TypeScript는 쓰지 않습니다.

## 시작하기

```bash
npm install
cp .env.example .env.local      # Firebase 설정값 5개를 채웁니다
npm run dev -- --host           # 같은 와이파이의 폰에서도 접속
```

`.env.local` (커밋 금지):

```
VITE_FB_API_KEY=
VITE_FB_AUTH_DOMAIN=
VITE_FB_DATABASE_URL=
VITE_FB_PROJECT_ID=
VITE_FB_APP_ID=
```

- Firebase 콘솔에서 프로젝트와 **Realtime Database**를 만들고 웹 앱을 등록해 값을 채웁니다.
- 폰 센서(흔들기)는 **HTTPS에서만 확실히 동작**합니다 (특히 iOS). 폰 테스트는 배포 주소나 터널(trycloudflare)로 하세요. 개발 서버는 `.trycloudflare.com` 호스트를 허용해 둡니다.
- 서버 없이 화면만 보고 싶다면 개발 서버 전용 미리보기가 있습니다: `/preview/cheer`, `/preview/battle`, `/preview/taunt`, `/preview/banner`, `/preview/host-battle`, `/preview/cutscene` (`?auto=1`을 붙이면 저절로 움직입니다).

## 배포

```bash
npm i -g firebase-tools
firebase login
firebase use --add              # 프로젝트 선택
npm run deploy                  # 빌드 + Hosting + DB 규칙 배포
```

- `.env.local` 값은 **빌드할 때** 코드에 들어갑니다. 값이 있는 컴퓨터에서 배포하세요.
- 화면 왼쪽 아래의 `빌드 MM.DD HH:mm`로 지금 보는 화면이 최신인지 확인할 수 있습니다.
- DB 규칙(`database.rules.json`)은 해커톤용으로 `rooms/` 전체가 열려 있습니다. **발표가 끝나면 닫으세요.**

## 발표 운영 순서

1. 전광판(`/host/kbo-lg-hh`)을 큰 화면에 띄우고 **화면을 한 번 눌러** 소리를 켭니다.
2. 팬들이 QR로 입장합니다.
3. 전광판 운영 컨트롤에서 이전 기록을 정리하려면 **경기 종료 → 경기 시작** (응원 점수가 0부터 다시 시작).
4. 필요하면 인원수 조작에서 발동 기준 인원과 표시 인원 가감을 맞춥니다.
5. 이의 있음이 모이면 자동으로, 아니면 **벤치클리어링 시작**으로 판정을 시작합니다.
6. 마지막에 **경기 종료**.

## 알려진 한계

- **아이폰은 진동이 되지 않습니다.** iOS Safari가 웹 진동 API를 지원하지 않습니다. 안드로이드 크롬에서만 울립니다.
- 아이폰에서 흔들 때 "실행 취소"가 뜨면 설정 → 손쉬운 사용 → 터치 → *흔들어서 실행 취소* 를 끄세요.
- 브라우저 정책상 **화면을 한 번 터치해야** 소리와 진동이 켜집니다.
- 현재는 **LG vs 한화 한 경기**(`kbo-lg-hh`)만 지원합니다. 다른 종목과 경기는 "준비중"입니다.
- 실제 경기 API와 연동하지 않습니다. 판정 순간은 팬이 직접 알립니다.
- 로그인이 없고 DB 규칙이 열려 있습니다 (발표 후 닫기).

## 에셋과 표현 원칙

- 실존 선수의 얼굴·이름, 구단 로고·워드마크는 쓰지 않습니다. 팀은 **이름 텍스트 + 팀 컬러**로만 표현합니다.
- 그림은 모두 코드로 그렸습니다. 폰트는 [Galmuri](https://github.com/quiple/galmuri)(OFL)입니다.
- `sound/`의 음원은 팀이 직접 준비한 것입니다. `cf/picxel.mp4`는 연출 참고용 자료이며 **앱에서 쓰지 않습니다.**
- 사용한 음원·영상의 사용 권한은 공개나 상업적 이용 전에 각자 확인해 주세요.
